# iA-Music 产品设计 v3 ·「黑胶金时代」

## 定位

一句话：**本地优先的个人音乐库——把散落的音乐收进来、看得清、听得好；UI 必须优雅。**

- 面向**自用为主**的个人音乐库，按**开源项目标准**打磨
- 最高验收原则：**优雅**。听音乐是优雅的行为——克制、仪式感、内容为本、字体气质、过渡动画（五义详见 [DESIGN.md](DESIGN.md)）
- 平台：**仅 Android（arm64）**

## 三根支柱

1. **入库**：本地文件夹扫描 + 在线提取（平台登录 → 站内搜索 → 选集 → 批量提取）
2. **曲库**：浏览（艺人/专辑/歌曲/歌单）、拼音即时搜索、封面与信息自动补全
3. **聆听**：本地播放、队列、逐行歌词、会话恢复

## 设计方向

**参照 Zune / WP7 黄金时代**：纯黑画布、细字重大标题、单一 accent、全景横滑。
设计语言、色板、组件语汇、动效与逐页规格全部收敛在 [DESIGN.md](DESIGN.md)，
PRODUCT 只定功能与信息架构。

## 信息架构

**纯横滑，无底部导航栏**；返回靠系统手势；迷你播放条吸底常驻（横滑 = 切歌）。

### Hub（主页，全景横滑）

| 屏 | 内容 | 说明 |
|---|---|---|
| 负一屏 | 听法 | 会话起点统一入口（见下节），细体大字列表 |
| 1 | 正在播放 | 上次会话大磁贴（封面 + 歌名 + ▶）；无会话时是「随缘听歌」磁贴 + 最近添加封面长廊，音乐仓库始终可见 |
| 2 | 曲库 | **歌曲列表**——全部歌曲按歌名字母排序，右缘字母导航轨，点击即播；底部「音乐页」入口（分类浏览） |
| 3 | 常听与历史 | 同上逻辑：计数行 + 两列网格（**常听单曲**，按播放次数排序，显示播放次数）+ 最近播放单曲网格（Zune History）；单曲磁贴**自动翻面**——背面露出播放次数（accent 大字）/歌名/歌手 |
| 4 | 歌单 | 同上逻辑：两列网格（歌单卡 → 歌单详情）；首位**新建歌单磁贴**（细线描边「+」，点按输入名字即建）；有封面的歌单磁贴**自动轮换两面**——正面封面、背面歌名/首数；页头不计数 |
| 屏末 | 设置 | 低调入口 → 设置页；**设置：主题色、存储（独立配置项 → 子页：音乐目录交互式更改、曲库统计、索引状态）、收集区块（平台登录、站内搜索）、语言、关于已并入设置页**，不再单独成屏 |

Hub 共 **6 屏**（负一屏 + 四主屏 + 设置）。屏序按使用习惯排布：高频在前（怎么听 → 在播 → 找歌），流水信息随后（常听历史 / 歌单），管理类靠后（设置）。

### 音乐页（分类菜单 + 列表页）

- **菜单页**：`音乐` 标题 + 分类浏览大字入口（艺人 / 专辑 / 歌曲 / 歌单，带数量）+ 流派 chips（点入流派详情）；搜索走应用栏 🔍，不设重复入口；Hub 曲库屏底部的「音乐页」入口到达
- **列表页**：点入分类后进入对应 pivot 列表（艺人 | 专辑 | 歌曲 | 歌单 四段横滑），歌曲/艺人/专辑列表带**右缘字母速查轨**
  （拖动时屏幕中央弹出大字母）。列表项**长按**呼出 WP 式上下文菜单；左缘右滑返回菜单
（播放 / 加歌单 / 喜欢 / 加入队列 / 查看专辑）。

### 搜索

- 入口 = 各 Hub 页页头右上角 🔍 + 曲库页/音乐页入口，一步可达
- 进页即聚焦键盘，**即时分组结果**：歌曲 / 艺人 / 专辑 / 歌单
- 拼音全拼 + 首字母命中；无输入时显示提示
- 点击 = 播放（连续动效飞升）；长按 = 上下文菜单
- **在线来源**：同一页内聚合搜索已登录的 B 站 / YouTube；点结果直接加入提取队列
- **从链接提取**：搜索页右上直达，粘贴 B 站 / YouTube / 直链音频链接逐条入队（进度见「设置 · 歌曲处理」）

### 播放域

- **Now Playing** = Pivot 三屏：`播放 | 歌词 | 队列`；播放屏**整页横滑 = 上一首/下一首**
- 歌词屏：纯黑，当前行 accent 细体大字，点行跳播，长按调偏移
- 队列屏：拖拽重排、移除、「下一首播放」插播
- 迷你条：封面 + 歌名 + accent 进度线，吸底；左右横滑切歌；点击展开 NP

## 播放方式

### 会话起点（一期全部）

| 方式 | 说明 |
|---|---|
| 顺序播放 | 集合按序播 |
| 集内随机 | 当前集合内打乱 |
| 随缘听歌 | 全曲库随机，hub 屏 1 磁贴一点即开 |
| 按专辑连播 | 完整专辑体验 |
| 常听 | 播放次数 Top N |
| 最近添加 | 新入库电台 |
| 喜欢电台 | 从红心歌出发随机 |
| 历史回放 | 播放历史直接变队列 |
| 歌单 | 人工集合 |
| 声音相似电台 | 以任一曲目为种子的声学近邻（设备端音频嵌入向量余弦 top-K，全离线；入口=曲目长按菜单「声音相似电台 ♪」，种子无向量时引导先跑补全） |

### 队列行为（一期全部）

循环模式（单曲循环 / 列表循环 / 随机不重复）、队列编辑（拖拽 / 移除 / 插播）、睡眠定时（15/30/60 分钟淡出）。

### 暂缓池（三期起，按需捞回）

艺人电台、年代电台、每日随缘、随机轮盘、无限电台、智能歌单、场景/心情标签（声音相似电台已随向量管道先行落地）。

## 内容来源

- **本地**：文件夹扫描入库，文件变动自动增量更新
- **插件系统（宿主中立）**：外部平台能力全部来自**插件**——官方音频源插件（B 站 / YouTube）作为数据资产随包**默认安装**（可停用/卸载/整文件升级，协议漂移改插件不发版），更多来源经市场（索引 URL 可自建）或本地导入 `.plugin.js`；宿主零编译态平台代码；规范见 docs/PLUGIN.md（能力族谱：音频源 / 歌词源 / 元数据补全源 / 歌单导入 / 流播放，按域扩展）
- **在线平台（迁移期并存）**：**B 站**（扫码登录）、**YouTube**（登录导入）——站内搜索 → 选集 → 批量提取，字幕自动转歌词；内置客户端验证插件化闭环后移除
- **从链接提取**：不登录不搜索，粘贴 B 站 / YouTube / 直链音频链接 → 逐条入提取队列，进度与失败重试在「设置 · 歌曲处理」
- **提取同名永不覆盖**：下载文件与音乐目录既有同名文件冲突时不删任何文件——内容相同去重复用既有文件，不同则换唯一名并存；用户的自有文件永不被收集管道改动或替换
- **存储（统一原则）**：所有音乐存放在**同一个音乐目录**（默认系统 Music 目录，可在「设置 · 存储」交互式更改），**曲库不区分来源**——提取结果与本地文件同等对待，无来源标记
- **凭据（自知）**：平台登录凭据保存在应用沙箱内，不外传；备份 / 导出曲库数据时会一并带出，注意保管
- **删除音乐（保守原则）**：删除一首歌只删音频文件并把曲目标记为缺失——歌单条目、播放历史、喜欢与歌词全部保留；文件放回原位重新扫描即复活
- **声音相似（在线模型）**：声学向量依赖设备端模型（YAMNet，约 16MB），**不随 APK 分发**——首次进入向量补全时自动从默认源下载（下载源可在设置 KV `models.yamnet.url` 指向自建直链），sha256 逐字节校验后落应用沙箱；离线设备跳过向量阶段不影响其余功能
- **补全管道（七阶段）**：缺失元数据的曲目自动入队——歌名/歌手（指纹→AcoustID→NLP 文字链投票）、歌词、封面（按需决议）、**专辑/音轨（AcoustID releases 来源；文字链无源，确认无也结案进灰档）**、声学向量（设备端模型）；进度在「设置 · 歌曲处理」逐阶段可见，跨重启续算；收集来的歌有了专辑/音轨即可进专辑分组浏览
- **编辑歌曲信息（只改库内显示）**：曲目长按菜单「编辑歌曲信息…」→ 编辑页改歌名/歌手/专辑/流派/音轨号、相册选封面、粘贴或导入 .lrc 歌词；只落库内显示字段与歌词 sidecar，**不写回音频文件 tag**；编辑即结论（补全管道不再回写覆盖），文件未被外部改动时编辑跨重扫保留

## 分期

### 一期（可发布纵切）

- 本地扫描入库 + Hub 六屏 + 收藏 pivot（字母速查）+ 详情页
- 搜索（即时分组 + 拼音）
- 播放域全套：队列/循环模式/睡眠定时、会话恢复、缺失跳过、后台/锁屏媒体会话
- 上表全部会话起点
- 歌词：内嵌 / .lrc / 在线歌词源，逐行沉浸、点行跳播、偏移调整
- 歌单 / 喜欢 / 历史
- Zune 设计系统 + accent 自选 + 动效三件套 + 首启 onboarding（两步：选色仪式 → 选音乐目录，完成即进 Hub）

### 二期

- 在线提取：B 站扫码、YouTube 登录、站内搜索、批量提取、字幕转歌词
- **元数据补全队列**：任何缺失歌手/歌词的曲目自动入队，音频指纹或在线匹配后写回库内标签，缺失期间以默认信息展示
- 封面自动补全（内嵌 → 在线匹配 → 色块兜底）
- 搜索页「曲库 | 在线」范围切换

### 三期（暂缓池）

听法扩展（见上）、云同步、语音识别歌词、EQ。

## 明确不做 / 暂缓

- Windows / Linux 桌面端（聚焦 Android；需要时回捞旧版）
- 浅色主题——黄金时代只有黑
- 平台之外的任何深度支持（网易云、QQ音乐等不做登录级集成）
- 把设计叙事写进代码注释——设计决策只活在 `docs/` 里
- 一次性铺开全部功能——每期都是可发布纵切
