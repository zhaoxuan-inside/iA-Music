## 问题与答复

### Q1. MVP 功能裁剪（核心假设 + CEO 裁剪）

- **题域**：范围裁剪
- **题干**：F1-F8 逐项是否入 MVP；单一核心假设推荐「本地曲库的沉浸式播放」
- **开发者答复**：**都是 MVP**（全部纳入）
- **采纳决策**：
  - F1 本地仓库扫描/元数据/播放/歌单 = MVP
  - F2 豆瓣 FM 式沉浸 UI + 三 Tab = MVP
  - F3 歌词显示（.lrc/内嵌标签）= MVP
  - F4 模型歌词提取（本地小模型）= MVP
  - F5 B 站/多站点提取入库（登录态高音质）= MVP
  - F6 云盘/GitHub 同步 = MVP
  - F7 三端（Android/Windows/Linux）= MVP（实施切片仍建议先核心闭环、后周边能力）
  - F8 增强（均衡器/音效、在线封面刮削等）= MVP（**Agent 解读：含 F8；若开发者本意为"仅 F1–F7"，请在轮 3 修正**）
- **关联落盘**：`_01_product_vision/_02_phased_roadmap/`（待生成）+ PRD 范围章

### Q3. 豆瓣 FM 交互本地化形态

- **题域**：产品交互
- **开发者答复**：**A 三 Tab 复刻（发现/搜索/我的）+ 沉浸播放页**；「发现」= 本地版私人兆赫；「我的」保留"本地曲库"入口卡。
- **采纳决策**：主交互形态锁定方案 A。

### Q4. 同步语义

- **题域**：对外契约 / 持久化
- **题干**：音频文件本体是否参与同步（方案 A 轻数据；方案 B 全量含音频本体）
- **开发者答复**：**B 全部同步（含音频文件本体上传/下载）**
- **采纳决策**：同步范围 = 歌单/元数据/歌词/播放记录/红心 **+ 音频文件本体**。
- **风险登记（OPEN）**：GitHub 通道存储大体积音频不现实（仓库大小/单文件 100MB 限制）；拟按「后端能力模型」处理——轻数据走全部通道（含 GitHub），音频本体走支持文件上传的云盘（WebDAV/OneDrive/GoogleDrive/百度网盘），GitHub 可选项=Release 附件（不建议）。**待轮 3 顺带确认。**

### Q5. 提取站点范围

- **题域**：对外契约
- **开发者答复**：**A 引擎能力制**（内嵌成熟下载引擎，覆盖其全部站点；B 站含登录态为重点保证）
- **采纳决策**：提取能力以引擎支持为准；B 站登录态/高音质为 MVP 重点。
