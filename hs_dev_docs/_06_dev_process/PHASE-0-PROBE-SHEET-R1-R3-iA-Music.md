## R1：Android 端下载引擎嵌入（B 站音频提取）— ISS-01

- **验收问题**：能否在 Android 端可靠解析 B 站分享链接、下载音频流并入库（含转码/元数据）？若不可行，降级方案（外部工具 / 自解析 API）能否接受？
- **限时**：≤60 分钟（桌面最小验证 20 分钟 + 集成方案对照 40 分钟）
- **桌面最小验证（步骤）**：
  1. 桌面安装 yt-dlp + ffmpeg → 取一个 B 站公开链接执行 `yt-dlp -x --audio-format mp3 <url>`；
  2. 记录：解析成功率、输出格式/比特率、耗时、失败模式（会员/风控/清晰度限制）。
- **桌面调研初稿（2026-10-17，含来源）**：
  - yt-dlp 本体内置 B 站（bilibili）extractor（1000+ 站点支持），Android 端两条主流嵌入路线 + 一条备选：
    - (a) `github.com/yausername/youtubedl-android`：yt-dlp 可执行封装库（内置 Python 3.8 runtime + 可选 ffmpeg 库；**支持库内更新 yt-dlp 二进制**，应对站点变更更稳）；YTDLnis（2026-09 仍活跃发版）基于该系库。
    - (b) `github.com/ffmpegkit-maintained/yt-dlp-android`（2026-07 新项目，MIT；v2.0.0 起改用 Chaquopy）：内嵌 CPython 3.13 的 AAR，~60–80MB，ABI 仅 arm64-v8a + x86_64，Android 7.0+；Java API 清晰，专为 Android impersonation 报错而做；**v2.0.0 不支持库内更新 yt-dlp**（需随库版本升级）；curl-cffi 指纹伪装为付费 Pro（$24）。
    - (c) 备选：NewPipe Extractor（纯 Java 解析、不含下载器；B 站支持）。
  - 共同代价：APK 体积 +50–80MB（可用 AAB + ABI splits 降低单机下载体积）；解析器需随站点变化更新——若选 (b) 需评估「无库内更新」的维护成本。
  - 成熟度提醒：(a) 生态最老最稳；(b) 非常新（2026-07 创建，社区规模小），若选型优先压测。
- **待环境验证（Android 真机）**：B 站链接解析成功率（普通/番剧/会员内容边界）、下载稳定性、后台任务表现、APK 体积实测。

## R2：百度网盘开放 API 能力边界（同步通道）— ISS-02

- **验收问题**：百度网盘能否作为「同步含音频本体」的通道？目录/权限/限速/审核边界是否可接受？
- **限时**：≤60 分钟（文档核对 30 + 最小授权流程尝试 30）
- **桌面调研初稿（2026-10-17，含来源）**：
  - 开放平台在营：接入流程文档 2026-08-10 更新；官方 Go SDK（分片上传）在列。**个人开发者可接入**（个人认证：最多 1 个应用；企业认证：10 个）——来源：`pan.baidu.com/union/apply`、`pan.baidu.com/union/doc`（使用入门/创建应用）。
  - 能力面：OAuth 2.0（scope=`basic,netdisk`；server 端推荐授权码模式）+ 基础网盘能力 API（文件管理 copy/move/rename/delete、分片上传「预上传→分片→创建文件」、dlink 下载）。
  - **关键约束（官方文档核实）**：每个第三方应用在网盘只能有一个文件夹，必须位于 `/apps/{appname}`（网盘内展示为「/我的应用数据/{appname}」）；且 **2026-06-03 之后创建的应用**，download / listall / filemanager / precreate / meta / move 六类接口仅允许访问 `/apps/{appname}` 目录。来源：`…/创建应用`（2026-08-03 更新）、`…/上传-能力说明`（2026-09-09 更新）、`…/权限与配额`（2026-07-03 更新）。
  - 上传限制：单文件上限 4GB（普通）/ 10GB（会员）/ 20GB（超会）；分片 ≤1024；仅对异常行为限频（正常使用不受影响）。
  - 应用用途两条路径：**个人使用（免审核、创建即上线、限 10 个用户）** vs **公开发布（需上线审核，通过后不限人数）**——开源/公开分发的产品需按「公开发布」路径评估。
  - 留白待查：《权限与配额》提到「权限内目录包括平台为应用生成的默认目录，以及**用户根据平台授权能力后续可能增加或调整的其他目录范围**」——用户目录授权能否扩充（影响「音频放用户自管目录」的可行性）待控制台实测确认。
- **待环境验证**：注册开发者 → 建应用（个人用途）→ OAuth 最小闭环（列出 `/apps` 目录、上传一个小文件、取 dlink 下载）；记录实际限速与失败率；顺带确认上述「目录范围扩充」机制是否可用。
- **产品裁决点**：是否接受「音频本体存于 `/apps/iA Music/` 目录」的约束（而非用户自管目录树）；若不接受 → 该通道降级为「仅轻数据同步」或移入 Phase 2 候选。

## R3：Android arm64 小模型推理（歌词生成 ASR）— ISS-03

- **验收问题**：Android arm64 能否离线跑中文 ASR 小模型，满足质量约束「生成耗时 ≤ 2× 音频时长」，且模型体积/下载体验可接受？
- **限时**：≤60 分钟（生态核对 30 + 桌面量化验证 30）
- **桌面调研初稿（2026-10-17，含来源）**：
  - `sherpa-onnx`（k2-fsa，来源：`github.com/k2-fsa/sherpa-onnx`）提供 **Android arm64-v8a 预编译产物**（AAR / so）；支持 Whisper（tiny 起）、SenseVoice、Paraformer、Zipformer、Qwen3-ASR 0.6B-int8 等**中文可用模型**；纯离线（onnxruntime），Kotlin API。
  - 生产案例：中国联通、中国人寿等 App 已在其正式版本中集成（2026 年）。
  - 轻量替代：whisper.cpp（来源：`github.com/ggerganov/whisper.cpp`；arm64 支持成熟）。
  - 体积参考：whisper tiny int8 ~75MB / base ~150MB 级；SenseVoice 更小、中文更优（以实测为准）。
  - 本机已有 onnxruntime 1.30.0 → 可先桌面 pip `sherpa-onnx` 做耗时/量化初验（未安装，装否由开发者决定）。
