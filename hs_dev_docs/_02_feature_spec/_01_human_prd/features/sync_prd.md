## 1. 特性洞察与核心价值界定 (Framing & Discovery)

- **现状与摩擦 (Status Quo)**：手机/电脑各有一份音乐与收藏；拷贝靠数据线/U 盘；在手机上红心的歌电脑上找不到；B 站提取的音频只存在一台设备。
- **用户雇佣任务 (JTBD)**：`When` 我在一台设备上补充了曲库/收藏/歌词，`I want to` 让其他设备自动拥有同样的音乐资产（包括音频文件本身），`so I can` 在哪里打开 iA Music 都能听到同一间"私人电台"。
- **惊喜时刻 (Aha Moment)**：手机上红心+提取的歌，走到电脑前打开应用——它已经在那里了。（辅助卖点 B，DEC-003 Q3）
- **冷启动体验 (FTUE)**：同步页引导选择通道（推荐 WebDAV 最稳）→ 填入地址/账号 → 连接测试 → 首次全量同步（带进度与预估）。

## 2. 交互形态比选与取舍 (Approaches & Trade-offs)

| 评估维度 | 方案 A（推荐采纳） | 方案 B（备选弃用） | 取舍理由 |
|---|---|---|---|
| **同步模型** | 用户自有存储（云盘/GitHub）为"中转仓库"，无自有服务端 | 自建同步服务器 | 隐私、零成本、与"本地优先"定位一致 |
| **数据分层** | 轻数据（歌单/元数据/歌词/历史/红心）走全部通道；重数据（音频本体）走文件型云盘 | 全部塞一个通道 | GitHub 不适合存音频（100MB/仓库限制），分层最稳（DEC-003 确认②） |
| **触发方式** | 变更后延迟自动同步（30s 防抖）+ 手动"立即同步" | 仅手动 | 接近"无感"，手动兜底 |
| **冲突策略** | 记录级"新修改者胜"（时间戳），冲突副本保留可回退；音频文件仅上传不覆盖（内容哈希相同跳过） | 弹窗逐条询问 | 批量冲突询问疲劳；保留副本以可恢复 |
| **删除传播** | 墓碑标记（记录不物理删除） | 级联物理删除 | 防误删（跨设备删除一台设备的内容不会毁掉云端资产） |

## 3. 详细字段与业务规则约束矩阵 (Specifications & Constraints)

### 3.1 通道配置字段

| 字段 | 通道 | 校验与边界 | 微文案 |
|---|---|---|---|
| 服务器地址/账号/密码 | WebDAV | 连接测试通过后保存；凭据加密存储 | "连接测试成功" |
| 授权登录 | OneDrive / Google Drive | OAuth 授权流程 | "已授权：user@example.com" |
| 仓库地址 + Token | GitHub | 用户提供私有仓库与访问 Token；仅轻数据 | "GitHub 仓库仅同步歌单/歌词/元数据，不存音频" |
| 远程目录 | 全部 | 默认 `iA-Music/` | — |
| 同步开关 | 全部 | 轻数据/音频文件本体 可分别开关 | 默认：轻数据开，音频开 |

### 3.2 同步对象与范围

| 类别 | 内容 | 通道要求 |
|---|---|---|
| 轻数据 | 曲目记录（含元数据）、歌单、红心、播放历史、歌词文件、仓库相对路径索引 | 全部通道（含 GitHub） |
| 重数据 | 音频文件本体（按内容哈希去重/校验） | 仅 WebDAV / OneDrive / Google Drive |

### 3.3 业务分支规则

1. **首次全量**：本地资产 → 远程（或远程 → 本地，首次引导中选择主设备；默认"合并，远程缺失项补到本地"）；
2. **路径迁移**：音频在不同设备的仓库根目录不同 → 用"仓库相对路径"匹配；文件名相同且哈希相同 → 视为同一文件（避免重复上传）；
3. **冲突**：同一曲目元数据在两台设备都被修改 → 保留新者 + 产生"冲突副本"记录（设置页可查看/删除）；歌单结构性冲突（曲目增删）→ 按集合合并（并集），删除以墓碑时间戳比较；
4. **网络/授权失败**：任务暂停，明示原因（网络/授权过期），恢复后继续；**本地数据不受影响**；
5. **空间**：上传不删除云端已有文件；下载前检查本地空间；
6. **多通道**：MVP 支持配置 1 个活跃通道（可切换）；多通道并存属 Phase 2。

### 3.4 状态与进度

同步中心展示：上次同步时间（`tabular-nums`）、待上传/待下载计数、当前任务进度（文件名+速度）、失败列表（可重试）、冲突副本入口。

## 4. 需求原子分解与行为驱动验收标准 (Requirements & Functional DoD)

### 4.1 核心需求原子分解清单

| 需求编号 | 需求名称与规则简述 | 关联动作 | 验收物理证据 | 优先级 |
|---|---|---|---|---|
| `REQ-SYNC-01` | 通道配置与连接测试 | 配置 WebDAV/OneDrive/Google Drive/GitHub | 测试通过才可保存；失败有具体原因 | P0 |
| `REQ-SYNC-02` | 轻数据同步（全通道） | 红心/歌单/歌词变更后 | 30s 内出现在远端；另一设备拉取后一致 | P0 |
| `REQ-SYNC-03` | 音频本体同步（文件型云盘） | 提取新歌后 | 音频上传成功；另一设备下载后可直接播放 | P0 |
| `REQ-SYNC-04` | 冲突处理 | 两设备先后修改同一曲元数据 | 新者胜 + 冲突副本可查看 | P0 |
| `REQ-SYNC-05` | 墓碑删除传播 | 设备 A 移除曲目 | 设备 B 该曲目移除记录；云端音频文件保留在云盘 | P0 |
| `REQ-SYNC-06` | 失败恢复 | 同步中断网 | 任务暂停明示原因；恢复网络后继续；本地无损 | P0 |
| `REQ-SYNC-07` | 手动同步与进度总览 | 点"立即同步" | 完整进度与结果摘要（成功 N/失败 M） | P0 |
| `REQ-SYNC-08` | GitHub 轻数据限制提示 | 配置 GitHub 通道 | 明示不传音频；音频开关对该通道不可用 | P0 |

### 4.2 行为驱动产品验收场景 (Gherkin Scenarios)

```gherkin
Feature: 多端同步

  Scenario: REQ-SYNC-02/03 跨端完整闭环 (Happy Path)
    Given 手机与电脑均已配置同一 WebDAV 通道
    When 手机端提取一首新歌并红心
    Then 30 秒内轻数据与音频文件上传完成
    When 电脑端打开应用并执行同步
    Then 该曲目记录、红心状态与可播放音频文件均出现在电脑端曲库

  Scenario: REQ-SYNC-05 墓碑删除不毁云端资产 (Guardrail)
    Given 同一账号下设备 A 与设备 B 曲库一致
    When 设备 A 从曲库移除《晚风》
    Then 设备 B 同步后曲库中《晚风》消失
    But 云盘中的《晚风》音频文件仍然存在可手动找回

  Scenario: REQ-SYNC-06 断网恢复 (Error Recovery)
    Given 同步任务进行中
    When 网络中断
    Then 同步中心显示「网络连接中断，任务已暂停，本地数据不受影响」
    When 网络恢复
    Then 任务自动继续并最终完成
```

## 5. 页面四态要求

- **Empty**：未配置通道 → 通道选择卡列表（WebDAV「最稳定推荐」/OneDrive/Google Drive/GitHub）+ 说明；
- **Loading**：首次全量同步进度（百分比 + 当前文件 + 速度）；
- **Populated**：同步中心总览（时间/计数/失败列表/冲突副本）；
- **Error**：授权过期/空间不足/连接失败 → 各自人话原因 + 原位操作（重新授权/清理/重试）。
