## 1. 特性洞察与核心价值界定 (Framing & Discovery)

- **现状与摩擦 (Status Quo)**：通用播放器界面冰冷、信息杂乱；想要"电台般的沉浸听歌"只能去在线 App，但那里没有自己的本地音乐。
- **用户雇佣任务 (JTBD)**：`When` 我想认真听一首歌或让音乐陪着做事，`I want to` 在极简沉浸的界面里控制播放（含不喜欢/跳过），`so I can` 不被打扰地进入音乐。
- **惊喜时刻 (Aha Moment)**：点击播放瞬间，封面像一帧胶片亮起（底边打孔、标签贴角），背面化为一整面模糊的光——歌词随唱随亮，只需要三个键就能掌控全场。
- **冷启动体验 (FTUE)**：首次播放自动进入沉浸播放页；空队列时提示"从你的曲库随机播放"一键开听。

## 2. 交互形态比选与取舍 (Approaches & Trade-offs)

| 评估维度 | 方案 A（推荐采纳） | 方案 B（备选弃用） | 取舍理由 |
|---|---|---|---|
| **播放页形态** | 复刻豆瓣 FM：模糊封面底 + 大封面 + 三键 + 红心 + 进度 | 顶栏封面条 + 大歌词区 | 保留已确认的视觉气质与交互结构（DEC-003） |
| **队列入口** | 播放页「更多 ⋯」与迷你条队列按钮 → 底部弹层 | 独立整页 | 弹层保沉浸上下文 |
| **不喜欢语义** | 垃圾桶 = 当前曲目移出随机播放池（可设置中恢复） | 永久删除曲目 | 对齐豆瓣 FM 心智；不误删收藏 |

## 3. 详细字段与业务规则约束矩阵 (Specifications & Constraints)

### 3.1 播放控制

| 项 | 规则与边界 | 默认值与微文案 |
|---|---|---|
| 播放/暂停 | 单击；全局热键（桌面空格）；媒体通知（Android） | — |
| 进度条 | 拖动预览时间；松手跳转；键盘 ←→ 5s 步进 | 时间 `tabular-nums` |
| 下一首/上一首 | 上一首：>3s 回到本曲开头，≤3s 切上首 | — |
| 循环模式 | 顺序 / 列表循环 / 单曲循环 / 随机（与音乐空间「随机」卡同一语义） | 默认：列表循环 |
| 倍速 | 0.5×/0.75×/1×/1.25×/1.5×/2× | 默认 1×；入口收在「更多」 |
| 垃圾桶（不喜欢） | 当前曲目加入"少播名单"；下一首自动触发；设置页可清空名单 | 首次点击 Toast："已减少这首的推荐" |
| 音量 | 桌面：系统键+页面滑杆；Android：系统音量 | — |

### 3.2 均衡器与音效（F8）

| 项 | 规则与边界 | 说明 |
|---|---|---|
| 预设 | 默认/流行/摇滚/古典/爵士/低音增强/自定义 | 默认=默认 |
| 自定义 EQ | 5 段（60Hz/230Hz/910Hz/3.6kHz/14kHz），±12dB | 拖动实时生效 |
| 生效范围 | 当前设备音频链路支持时生效；不支持时页内明示"当前设备不支持音效调节" | 诚实微文案 |
| 淡入淡出 | Phase 2（本期不做） | — |

### 3.3 业务分支规则

1. **队列**：播放来源（歌单/曲库/随机）生成的列表进入队列；队列可查看、跳选、清空；临时"下一首播放"插队；
2. **文件缺失曲目**：播放时命中缺失文件 → 跳过并顶部提示"《X》文件缺失已跳过”，自动继续下一首；
3. **音频格式**：优先支持 MP3/FLAC/AAC/M4A/WAV/OGG；遇到不支持格式 → 行内标记"格式不支持"（灰显，可尝试仍播放）；
4. **随机会话（胶片页，DEC-004）**：从音乐空间「随机」卡进入的播放会话 = 随机模式（随机池 = 全库 − 少播名单，单轮不重复）；顶栏标题显示「随机」；此页封面以**胶片帧**呈现（外框 `#0D0F11` r18、画面 r10、下缘风格标签芯片 ≤2 个、框底打孔带）；无标签数据时隐藏芯片区；标题左对齐 + 心动于右、头像+歌手行（⋯ 展开队列）、三行歌词预览（点击进歌词页）、进度条白色圆点；随机会话另有**轮盘视图**（`#p-shuffle`，DEC-006 D6-7，轮 16 终稿已确认）：经典兆赫唱片轮盘、仅上滑/播完自动切歌——与胶片页共享同一随机池、当前曲与「下一首」语义；
5. **胶片帧封面来源**：内嵌图/同目录图/自动抓取封面（FEAT-LIB-01 REQ-LIB-08）；均无 → 首字母色块同帧呈现。

### 4.2 行为驱动产品验收场景 (Gherkin Scenarios)

```gherkin
Feature: 沉浸式播放与播放增强

  Scenario: REQ-PLAY-01 点击播放进入沉浸页 (Happy Path)
    Given 曲库中有《夜航》且文件存在
    When 用户在曲库列表中点击《夜航》
    Then 300ms 内开始出声并进入沉浸播放页
    And 页面背景为该曲封面驱动的模糊色，封面以胶片帧（打孔带）呈现，标题/歌手正确展示

  Scenario: REQ-PLAY-01b 随机一触即听 (Film Page = Random)
    Given 曲库中有 200 首可播放曲目且无少播名单
    When 用户在音乐空间页点击「随机」卡片
    Then 立即随机开播并进入胶片式播放页，顶栏显示「随机」
    And 连续"下一首"在随机池内不重复直到一轮播完

  Scenario: REQ-PLAY-04 垃圾桶行为 (Dislike)
    Given 用户正在随机模式听《夜航》
    When 用户点击垃圾桶图标
    Then 立即切到下一首，且《夜航》加入少播名单
    And 在设置中清空少播名单后，《夜航》可重新被随机到

  Scenario: REQ-PLAY-08 缺失文件跳过并提示 (Error Recovery)
    Given 队列下一首《旧信》的文件已被外部删除
    When 播放进行到该曲
    Then 自动跳到再下一首并顶部提示「《旧信》文件缺失，已跳过」
    And 播放队列状态与当前曲目信息保持正确
```

## 5. 页面四态要求

- **Empty**：队列为空 → "从你的曲库随机播放"★ CTA；
- **Loading**：播放页封面加载前 → 首字母色块占位（无骨架假图）；
- **Populated**：完整沉浸页；
- **Error**：音频解码失败 → 原位提示"无法播放该文件（格式或文件损坏），已跳过"。
