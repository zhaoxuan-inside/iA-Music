## 1. 特性洞察与核心价值界定 (Framing & Discovery)

- **现状与摩擦 (Status Quo)**：音乐散落在手机存储、电脑硬盘、移动硬盘多处；靠文件夹 + 通用播放器凑合；新歌入库靠手动拷贝改文件名。
- **用户雇佣任务 (JTBD)**：`When` 我新下载/提取了一批音乐，`I want to` 让它们自动出现在一个统一曲库里（带正确歌名/歌手/封面），`so I can` 随时按歌手/专辑/风格找到它们并直接播放。
- **惊喜时刻 (Aha Moment)**：指定目录后，几百首歌在 1 分钟内带着封面整齐出现在曲库——零手工整理。
- **冷启动体验 (FTUE)**：引导页选目录 → 即时显示扫描进度与"已发现 N 首"计数 → 扫描完成直接进入曲库。

## 2. 交互形态比选与取舍 (Approaches & Trade-offs)

| 评估维度 | 方案 A（推荐采纳） | 方案 B（备选弃用） | 取舍理由 |
|---|---|---|---|
| **仓库配置形态** | 设置页集中管理多仓库（增删/扫描/状态），曲库页只展示结果 | 首页内嵌"添加目录"大按钮 | 仓库配置是低频操作，收进设置符合渐进式披露 |
| **扫描触发** | 自动（启动增量 + 目录变更监听）+ 手动"重新扫描" | 仅手动扫描 | 自动优先，"重新扫描"兜底；用户无需操心 |
| **元数据来源优先级** | 内嵌标签 > 文件名解析 > 在线封面刮削补缺 | 仅内嵌标签 | 兼容无标签文件；刮削仅补封面不覆盖已有数据 |

## 3. 详细字段与业务规则约束矩阵 (Specifications & Constraints)

### 3.1 仓库字段

| 字段/参数名 | 披露层级 | 类型 | 必填 | 校验规则与边界 | 默认值与微文案 |
|---|---|---|---|---|---|
| 仓库路径 | 设置首屏 | 目录路径 | 是 | 必须存在且可读；同一路径不可重复添加；不可为另一个仓库的子目录 | "选择音乐所在文件夹" |
| 仓库名称 | 设置折行 | 字符串 | 否 | 1–30 字符；默认取文件夹名 | 默认：文件夹名 |
| 自动扫描 | 设置折行 | 开关 | 否 | 默认开 | 打开后目录内变化自动入库 |

### 3.2 曲目字段（展示与编辑）

| 字段 | 类型 | 校验与边界 | 备注 |
|---|---|---|---|
| 标题 | 字符串 | 1–200 字符；空则回退文件名 | 可编辑（原文件保持不动，只改曲库记录） |
| 歌手 | 字符串 | 0–100 字符；多歌手以 `/` 分隔 | 默认取标签/解析 |
| 专辑 | 字符串 | 0–100 字符 | |
| 封面 | 图片 | 内嵌图 > 同目录同名图 > 在线搜索 > 首字母色块 | **默认自动**：无任何封面来源时联网搜索并保存到本地（`<文件名>.cover.jpg` 同目录文件，不覆盖、不改音频本体）；设置可关闭 |
| 音质信息 | 只读 | 格式/码率/采样率 | 列表次级信息 |

### 3.3 业务分支规则矩阵

1. **常规成功**：扫描 → 解析元数据 → 入库 → 曲库页按"最近入库"可见；
2. **无标签文件**：文件名解析（"歌手 - 歌名"模式）→ 仍无法解析则标题=文件名、歌手=未知歌手，标记可手工编辑；
3. **文件被外部移动/删除**：下次扫描检测到断链 → 曲目标记"文件缺失"（灰显 + 定位提示），不删除记录等待用户处理（误拔移动硬盘场景）；
4. **封面抓取**：默认开启；无任何封面来源（无内嵌图、无同目录图）时自动联网搜索封面 → 保存为音频同目录封面文件 → 播放/列表即时展示；不覆盖内嵌图与已有封面文件；离线或无匹配结果 → 静默使用首字母色块，下次扫描/播放时重试，全程不阻塞入库与播放。

## 4. 需求原子分解与行为驱动验收标准 (Requirements & Functional DoD)

### 4.1 核心需求原子分解清单

| 需求编号 | 需求名称与规则简述 | 关联动作 | 验收物理证据 | 优先级 |
|---|---|---|---|---|
| `REQ-LIB-01` | 添加仓库并全量扫描入库 | 设置页"添加音乐仓库"→选目录 | 进度可观察；完成后曲库计数 = 实际音频文件数 | P0 |
| `REQ-LIB-02` | 启动增量扫描与变更监听 | 应用启动 / 目录内新增文件 | 新增文件 ≤15s 出现在曲库 | P0 |
| `REQ-LIB-03` | 元数据解析与手工编辑 | 曲目详情编辑标题/歌手/专辑 | 编辑后列表与播放页即时更新；原文件不被修改 | P0 |
| `REQ-LIB-04` | 封面展示与来源链 | 播放/浏览任意曲目 | 按来源链展示：内嵌图 > 同目录图 > 自动抓取（REQ-LIB-08）> 首字母色块；不覆盖已有封面 | P0 |
| `REQ-LIB-05` | 文件缺失与恢复 | 外部移动仓库内文件 | 曲目灰显"文件缺失"；文件放回后自动恢复可用 | P0 |
| `REQ-LIB-06` | 曲库浏览与排序 | 列表内按歌手/专辑/最近/时长排序 | 排序即时生效且不卡顿（1 万首） | P0 |
| `REQ-LIB-07` | 移除曲目（解除入库） | 曲目行菜单"从曲库移除" | 记录消失；**本地音频文件保留** | P0 |
| `REQ-LIB-08` | 无封面自动联网搜索并本地保存 | 播放/浏览一首无任何封面的曲目 | 联网搜索到封面 → 同目录生成封面文件并即时展示；无结果/离线 → 首字母色块不报错 | P0 |

### 4.2 行为驱动产品验收场景 (Gherkin Scenarios)

```gherkin
Feature: 音乐仓库与曲库管理

  Scenario: REQ-LIB-01 添加仓库并完成首次扫描 (Happy Path)
    Given 用户首次进入引导页且尚未配置任何仓库
    When 用户选择了一个含 500 首音乐的有效目录并确认
    Then 界面展示扫描进度与"已发现 N 首"实时计数
    And 扫描完成后自动进入音乐空间，曲库计数为 500

  Scenario: REQ-LIB-05 文件缺失的容错与恢复 (Error Recovery)
    Given 曲库中存在曲目《夜航》，其文件位于仓库内
    When 用户在系统文件管理器中把该文件移动到仓库之外
    And 触发下一次扫描
    Then 《夜航》显示灰色"文件缺失"状态与"定位文件"操作
    When 用户把文件放回仓库原位置并再次扫描
    Then 《夜航》自动恢复为可播放状态，无需重新入库

  Scenario: REQ-LIB-07 移除曲目不删物理文件 (Guardrail)
    Given 曲库中有一首曲目，文件位于仓库目录内
    When 用户在行菜单选择"从曲库移除"并确认
    Then 曲目从曲库与歌单中消失
    But 仓库目录中的音频文件仍然存在

  Scenario: REQ-LIB-08 无封面自动抓取并本地保存 (Cover Fetch)
    Given 曲目《旧信》没有任何内嵌封面与同目录封面，且设置中封面抓取为开启
    When 用户扫描完成并播放《旧信》
    Then 应用联网搜索到匹配封面并保存为音频同目录封面文件
    And 播放页与列表立即展示该封面
    But 用户已有封面的其他曲目不会被覆盖，音频文件本体未被修改
```

## 5. 页面四态要求（本特性相关）

- **Empty**：曲库无曲目 → "还没有音乐。选择一个音乐文件夹，或粘贴一条 B 站链接试试" + 两个 CTA（选择目录 ★ / 提取链接）；
- **Loading**：扫描中 → 进度条 + 实时计数（不做假骨架）；
- **Populated**：曲库列表（排序/筛选 chip + 行）；
- **Error**：目录不可读/被拔出 → "音乐仓库『移动硬盘』无法访问，请重新连接或移除该仓库"，保留其余曲库可用。
