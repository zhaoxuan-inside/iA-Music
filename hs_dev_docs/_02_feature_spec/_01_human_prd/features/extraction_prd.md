## 1. 特性洞察与核心价值界定 (Framing & Discovery)

- **现状与摩擦 (Status Quo)**：B 站上听到好音乐 → 第三方工具下载 → 手工改文件名 → 手动拷贝到音乐文件夹 → 播放器里还不一定有封面；链路 5+ 步且工具散落。
- **用户雇佣任务 (JTBD)**：`When` 我在 B 站刷到一首想收藏的音乐视频，`I want to` 粘贴分享链接就让它带着正确标题/封面/歌唱信息进入我的本地曲库，`so I can` 在同一个播放器里沉浸收听，不用离开音乐世界。
- **惊喜时刻 (Aha Moment)**：粘贴链接 → 解析出歌名/UP 主/时长 → 一键提取 → 几秒到几分钟后，它已经躺在曲库里，封面歌词齐全，点开就是沉浸播放页。（主 Aha，DEC-003 Q3）
- **冷启动体验 (FTUE)**：提取页空态 → 输入框聚焦提示"在 B 站点分享→复制链接，粘贴到这里"；含真实示例占位链接逻辑（不造假数据，仅格式示例）。

## 2. 交互形态比选与取舍 (Approaches & Trade-offs)

| 评估维度 | 方案 A（推荐采纳） | 方案 B（备选弃用） | 取舍理由 |
|---|---|---|---|
| **入口形态** | 独立「提取」页（粘贴框 + 任务队列） | 设置里藏一个对话框 | 提取是主 Aha 路径，需要一等公民入口；且在「音乐空间」页与空态多处给快捷入口 |
| **音质选择** | 解析后显示可选音质（B 站登录后可选高码率），默认最高可用 | 静默最高 | 用户知情；登录态价值可见（高音质） |
| **多任务** | 多链接排队串行下载，可离开页面后台进行 | 一次一个，禁止离开 | 批量收藏场景刚需（专栏合集/多 P 视频） |
| **登录态** | B 站扫码登录（应用内展示二维码）；Cookie 加密存本机 | 手动填写 Cookie | 扫码对普通用户零门槛 |

## 3. 详细字段与业务规则约束矩阵 (Specifications & Constraints)

| 项 | 规则与边界 | 默认值与微文案 |
|---|---|---|
| 链接输入 | 支持 B 站分享文本（含"【标题】链接"整段）、纯链接；自动从文本中提取 URL；支持多 P/合集的多选 | 占位符："粘贴 B 站分享链接" |
| 支持站点 | 引擎能力制：覆盖引擎支持的全部站点；**B 站为重点保证（含登录态高音质）** | 解析失败文案见下 |
| 解析结果 | 展示：标题、来源 UP 主/作者、时长、封面、可选音质列表 | — |
| 音质 | B 站：未登录 → 可用码率；登录 → 高码率（对应设备可用） | 默认选最高可用 |
| 保存位置 | 默认 `仓库/提取/` 子目录（设置可改） | 首次提取时说明"将保存到 音乐仓库/提取/" |
| 文件命名 | `歌手 - 歌名.ext` 规整化；元数据写入：标题=视频标题净化，歌手=UP 主 | 净化规则：去「」【】书名号与合集前缀 |
| 任务队列 | 串行下载；每任务显示进度/速度（可关闭）；支持取消 | 完成后 Toast："《X》已加入曲库" |
| 后台/网络 | 桌面与移动均支持页外继续；断网自动暂停、恢复后继续 | 明示"下载中断，已暂停，联网后自动继续" |
| 歌词联动 | 提取完成后可勾选"同时生成歌词"（接入 FEAT-LYR-02） | 默认勾选（已下载模型时）/ 不勾选（未下载时） |
| 合规 | 首次使用展示声明：仅限个人备份可合法访问的内容，遵守平台条款；需确认后继续 | 声明一屏，可回看 |

### 业务分支规则

1. **链接失效/需登录**：解析失败 → "链接解析失败：链接可能已失效，或该内容需要登录。登录 B 站账号后重试"；
2. **音质不可用**：所选码率在下载时失效 → 自动降级最高可用并在任务中标注"已降级至 XX"；
3. **重复提取**：曲库已有同来源视频 → 提示"这首歌已在曲库中（匹配来源链接）"，可选择重新提取或跳过；
4. **磁盘空间不足**：下载前检查可用空间 → 不足时任务挂起提示"存储空间不足，请清理后重试"；
5. **删除**：任务历史可清除；已入库曲目按曲库移除规则处理（不删文件需确认——按总览删除策略，移除记录不删文件）。

### 4.2 行为驱动产品验收场景 (Gherkin Scenarios)

```gherkin
Feature: 分享链接音频提取入库

  Scenario: REQ-EXT-01/03 主 Aha 路径 (Happy Path)
    Given 用户已配置音乐仓库并已确认合规声明
    When 用户粘贴一条 B 站音乐视频分享文本并点击"开始提取"
    Then 5 秒内展示解析结果（标题、UP 主、时长、封面、音质选项）
    When 用户选择最高音质并点击"开始提取"
    Then 任务进入队列并显示下载进度
    And 完成后提示「《X》已加入曲库」，曲库中该曲带封面与元数据

  Scenario: REQ-EXT-05 链接失效的人话错误 (Error Recovery)
    Given 用户粘贴了一条已失效的视频链接
    When 用户点击"解析链接"
    Then 原位显示「链接解析失败：链接可能已失效，或该内容需要登录。你可以登录 B 站账号后再试」
    And 输入框中的链接内容完整保留

  Scenario: REQ-EXT-02 登录后高音质 (Login State)
    Given 用户未登录 B 站，当前最高可选音质为普通码率
    When 用户完成扫码登录后重新解析同一条链接
    Then 音质选项中出现高码率并被默认选中
```

## 5. 页面四态要求

- **Empty**：粘贴框 + "如何获取 B 站分享链接（三步图示）"引导 + 历史任务空态；
- **Loading**：解析中（按钮内 Spinner）/ 下载中（进度、速度、剩余时间，可折叠）；
- **Populated**：解析结果卡 + 任务队列（进行中/已完成分组）；
- **Error**：解析失败/下载失败/空间不足 → 各类人话原因 + 原位重试按钮；队列任务失败保留在列表可单条重试。
