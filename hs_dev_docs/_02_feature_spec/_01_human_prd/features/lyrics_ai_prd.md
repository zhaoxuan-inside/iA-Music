## 1. 特性洞察与核心价值界定 (Framing & Discovery)

- **现状与摩擦 (Status Quo)**：冷门歌/B 站翻唱/纯音乐没有任何歌词来源；手工听写不现实，网上找 LRC 常常没有。
- **用户雇佣任务 (JTBD)**：`When` 我有一些没有任何歌词的老歌/翻唱，`I want to` 用本地模型一键生成带时间轴的歌词，`so I can` 让它们也能被跟着唱，而不是永远"哑巴"。
- **惊喜时刻 (Aha Moment)**：一首 4 分钟的陌生翻唱，几分钟后屏幕上出现了逐行同步的歌词——而且全程没有联网、没有上传任何音频。
- **冷启动体验 (FTUE)**：首次使用该功能 → 引导下载小模型（显示体积与一次即可），下载后立即可用。

---

## 2. 交互形态比选与取舍 (Approaches & Trade-offs)

| 评估维度 | 方案 A（推荐采纳） | 方案 B（备选弃用） | 取舍理由 |
|---|---|---|---|
| **模型方案** | 本地小模型（Whisper 级 tiny/base 量化版），内置多语言 | 云端 ASR API | 隐私（音频不出本机）+ 零费用 + 离线可用；精度换体积，匹配"小模型"要求（DEC-001） |
| **触发方式** | 单曲手动触发 + 支持批量勾选排队 | 全库自动（后台偷偷跑） | 计算重、尊重用户设备；批量排队兼顾效率 |
| **结果处理** | 生成后预览（可编辑）→ 保存 .lrc | 直接落盘 | 用户可修错字/删气泡音行，避免污染歌词资产 |

## 3. 详细字段与业务规则约束矩阵 (Specifications & Constraints)

| 项 | 规则与边界 | 默认值与微文案 |
|---|---|---|
| 模型管理 | 首次使用引导下载；设置页显示模型体积/已用空间；可删除模型 | "音乐识别模型（约 XXX MB，仅需下载一次）" |
| 触发 | 单曲：歌词页/行菜单"生成歌词"；批量：多选曲目 → "批量生成歌词" | — |
| 队列 | 生成任务串行排队（避免占满 CPU）；可暂停/取消/查看进度 | 进度按曲目展示（第 2/5 首） |
| 输出格式 | LRC（行级时间戳 + 文本） | 保存为同目录 `.lrc`（与 FEAT-LYR-01 同一资产） |
| 语言 | 自动检测（中文/英文为主）；纯音乐无歌词 → 提示"未检测到人声" | — |
| 精度预期 | 明示"AI 生成歌词可能有错漏，请预览校正" | 诚实微文案 |
| 取消 | 任务进行中可取消，不产生半成品文件 | — |
| 后台策略 | 移动端：仅前台+亮屏或有前台服务时执行；桌面：可后台 | 移动端提示"保持应用在前台以获得更快速度" |
| 并发 | 同时最多 1 个推理任务 | — |

### 业务分支规则

1. **已有歌词**：曲目已有 .lrc → 触发时提示"已有歌词，生成将需确认覆盖"；
2. **备用音轨/无伴奏**：正常处理（不需要特殊分支，ASR 对纯器乐返回空）；
3. **失败重试**：单曲失败（文件损坏等）→ 队列中标记失败原因，可单独重试；
4. **性能目标**：4 分钟歌曲 ≤ 2 分钟完成（中端桌面）；Android 端目标 ≤ 2 倍时长；超限时在队列中明示进度百分比（兑现 PROD-08 约束）。

## 4. 需求原子分解与行为驱动验收标准 (Requirements & Functional DoD)

### 4.1 核心需求原子分解清单

| 需求编号 | 需求名称与规则简述 | 关联动作 | 验收物理证据 | 优先级 |
|---|---|---|---|---|
| `REQ-LYRAI-01` | 首次模型下载与就绪 | 首次点"生成歌词" | 引导下载 → 完成 → 按钮就绪 | P0 |
| `REQ-LYRAI-02` | 单曲生成与进度 | 单曲"生成歌词" | 显示进度百分比；完成后进入预览 | P0 |
| `REQ-LYRAI-03` | 批量排队与串行处理 | 多选 5 首批量生成 | 队列逐一处理；可暂停/取消 | P0 |
| `REQ-LYRAI-04` | 结果预览与编辑保存 | 生成完成 → 修改错别字 → 保存 | 保存为 .lrc；歌词页立即可用 | P0 |
| `REQ-LYRAI-05` | 无歌词/纯音乐处理 | 对纯音乐生成 | 明确提示"未检测到人声"，不生成空文件 | P0 |
| `REQ-LYRAI-06` | 离线可用 | 断网状态下生成 | 生成流程不依赖网络（模型已下载后） | P0 |

### 4.2 行为驱动产品验收场景 (Gherkin Scenarios)

```gherkin
Feature: 模型歌词提取

  Scenario: REQ-LYRAI-01/02/04 首次生成闭环 (Happy Path)
    Given 用户首次对《旧信》点击"生成歌词"且模型尚未下载
    When 用户确认下载模型并等待完成
    Then 生成任务自动开始并在界面显示实时进度百分比
    When 生成完成，用户在预览中修正一处错字并点击"保存歌词"
    Then 同目录生成《旧信.lrc》，歌词视图立即逐行高亮

  Scenario: REQ-LYRAI-05 纯音乐处理 (Validation)
    Given 用户对一首纯器乐曲触发"生成歌词"
    When 推理完成
    Then 提示「未检测到人声，未生成歌词文件」，且不产生任何 .lrc 文件

  Scenario: REQ-LYRAI-06 离线可用 (Constraint)
    Given 模型已下载完成，设备处于断网状态
    When 用户对任意曲目触发"生成歌词"
    Then 生成流程正常完成
```

## 5. 页面四态要求

- **Empty**：无生成任务 → 说明文案 + "选择歌曲生成"入口；
- **Loading**：模型下载中（进度条 + 体积）+ 推理中（单曲进度百分比）；
- **Populated**：任务队列列表（等待/进行中/完成/失败分组）；
- **Error**：模型下载失败 → "下载失败：检查网络后重试"，可换源重试（实现期定义镜像策略）。
